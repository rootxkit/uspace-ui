# uspace-ui

Shared npm UI kit of the U-space systems (`uspace-cisp`,
`uspace-authority`, `uspace-ussp`, `uspace-ansp`, `uspace-lab`):
shadcn/ui theme and design tokens, MapLibre map components and layers
(zones by type and restriction state, tracks by trust class,
identification status and age, alerts, intents, manned traffic, Remote
ID receivers) with their legends, `ka`/`en` i18n with Noto Sans
Georgian, a live-feed client with source and degraded-state components,
accessible table and form kits, a typed adapter for each system's
OpenAPI-generated client, and the BFF session helpers (cookie, CSRF,
forwarding) for Next.js.

A library, not a service: no process, no port, no database, no NATS, no
image. It renders what each system's API says and judges nothing;
every safety judgement lives once in Go, in
[`uspace-core`](https://github.com/rootxkit/uspace-core). Each system's
`web/` pins an exact version and maps its generated API types onto the
kit's view models in an adapter it owns.

consoles use them. Distribution is npmjs only, with provenance; every
consumer installs with pnpm and an exact pin.

### API types (`uspace-ui-gen-api`)

Every `web/` generates its API types from its system's
`api/openapi.yaml` with the bin this package ships, which pins
openapi-typescript so all five apps generate the same way, and writes a
first line `// @generated by uspace-ui-gen-api <version> (openapi-typescript
<version>) from <sha256 of the input>; do not edit` that the kit's
`no-hand-written-api-types` lint rule recognises. Never edit the output.
The three lines a `web/` adds:

```jsonc
// web/package.json "scripts"
"gen:api": "uspace-ui-gen-api ../api/openapi.yaml src/api/generated/openapi.d.ts",
"check:api": "uspace-ui-gen-api ../api/openapi.yaml src/api/generated/openapi.d.ts --check",
```

```yaml
# web/ CI, after pnpm install --frozen-lockfile: fails when the committed types are stale
- run: pnpm check:api
```

Exit codes: `0` written or current, `1` `--check` found the output
missing or different, `2` a usage error or an input that does not
generate. Commit the output and list it in `.prettierignore`, so a
formatter does not make `--check` fail. Then:

```ts
// web/src/api/client.ts
import { createClient } from "@rootxkit/uspace-ui/api";
import type { paths } from "./generated/openapi.js";
export const api = createClient<paths>({ baseUrl: "/_bff/api", csrfToken, lang, onUnauthorized });
```

A non-2xx answer rejects with an `ApiError` (`status`, `problem`,
`slug`, `retryAfterS`, `requestId`, `sunset`); the client never
retries.

Entry points: `@rootxkit/uspace-ui/{model,theme,ui,i18n,fonts,map,api,
auth/server,auth/client,symbology,layers,legend,live,status,alerts,
table,form,eslint,test}`. The full step list for a `web/` app is in
`docs/CONSUMING.md` (WP-13).

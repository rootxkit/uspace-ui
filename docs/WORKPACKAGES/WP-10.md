# WP-10: `form` (form kit with API field errors, units, UTC and confirmed acts)

Branch `feat/WP-10-form`. Milestone U-M2 (registry authoring at the
authority, zone authoring, intents at the USSP portal, restrictions at
the ANSP, subscriptions at the CISP). Owns `src/form/` exclusively.
Depends on WP-1 (`ui`), WP-2 (formatters, i18n), WP-4 (`FieldError`,
`ApiError`). Consumers: every console and the operator portal; WP-8's
`SourcesPanel` switches to `ConfirmDialog` once this lands.

## Read first

1. `docs/PLAN.md` §3.1 (`FieldError`, `Problem`), §3.15, §14 Q2.
2. Spec `02 §1` (RFC 3339 UTC with `Z`; altitudes with explicit
   reference; `[lng, lat]`), `02 F1` (the ED-318 fields a zone form
   edits; the limits with `m`/`ft` and `AGL`/`AMSL`/`WGS84`), `02 F5`
   (the ten Annex IV items of an intent request: the operator portal's
   biggest form; the kit supplies fields, the USSP supplies the schema),
   `02 §1` failure rule ("every disable is an audited act by a person"),
   `01` A10 (audit of every change), `06 §5`.
3. `uspace-core` `CLAUDE.md` rule 5 and `docs/PLAN.md §8.7`: an error
   names the field as a JSON path (`features[3].geometry[0].upperLimit`)
   or a wire offset; `ed269.Problems` lists up to 100 and a `Truncated`
   count. The form kit renders exactly that.
4. LESSONS Z-02 (import all or nothing, name every problem: the form
   shows the whole list, not the first), E-13 (unit and datum in the
   label), S-16 (UTC in the input label), B-09/B-11 (a switch has a
   reason and a person), D-01 (a form never offers AGL and AMSL in one
   number), INV-03 (no threshold default in a form).
5. react-hook-form, zod and `@hookform/resolvers` documentation
   (pinned versions). WAI-ARIA form patterns (`aria-describedby` for
   errors, `aria-invalid`, live region for the error summary).
6. Predecessor `utm/web-pilot/src/components/ZoneEditor.tsx` (the
   fields a zone needs; its client-side validation is *not* ported
   beyond "required" and "is a number": the API validates with the
   strict reader).

## What to build

- `Form<Schema>`: react-hook-form with the zod resolver; `onSubmit` may
  return `FieldError[]` (or throw an `ApiError` whose `problem.errors`
  is used): each error is mapped onto the registered field whose name
  equals the JSON path (dots and brackets normalised both ways), the
  rest go to `FieldErrors` at the top with the path shown; an error
  summary live region announces the count; submit disabled while busy;
  a `Retry-After` from the API shown as a countdown on the submit
  button.
- `Field` with label, required mark, `unit` and `datum` *in the label
  text* ("Upper limit (m, AMSL)"), hint, error wiring
  (`aria-describedby`, `aria-invalid`); `NumberField` (locale-aware
  input, stores a number, null when empty, never `0`), `TextField`,
  `SelectField`, `CheckboxField`, `EnumField<E>` (options from a
  `model` array with i18n labels), `UTCDateTimeField` (label ends with
  "UTC"; value RFC 3339 with `Z`; a browser's local `datetime-local`
  is converted at the boundary and the test proves no drift across DST),
  `BBoxField` (four numbers in `[lng, lat]` order with the order in the
  labels), `ReasonField` (a mandatory free-text reason with a minimum
  length prop).
- `ConfirmDialog` for audited acts: title, body, optional mandatory
  reason, destructive styling, `onConfirm(reason)`; the primary action
  is not focused by default when `destructive` (a stray Enter must not
  confirm).
- `FieldErrors` list with the truncation note when the API says it
  truncated.

## Tests

- jsdom: an API `FieldError` with path `features[0].properties.name`
  lands on the field registered as `features.0.properties.name` and the
  summary count is 1; an error with an unknown path lands in
  `FieldErrors` with the path text (pair); 100 errors plus a truncation
  flag render the note; submit disabled while the promise is pending
  and re-enabled after (both branches); a successful submit clears
  previous errors (E-02: the success path is read); `Retry-After`
  countdown.
- Fields: `NumberField` empty → `null` not `0`; `"1,5"` in `ka` locale
  parses as 1.5 (locale decimal) and `"1.5"` in `en`; the label text
  contains the unit and the datum when given and nothing in brackets
  when not (pair); `UTCDateTimeField` label ends with "UTC" in both
  languages; round trip of `2026-03-29T00:30:00Z` through the field in
  a `Europe/Tbilisi` and a `Europe/London` fake timezone returns the
  same instant (DST edge); `BBoxField` rejects `minLng > maxLng` with a
  field error naming the pair; `EnumField` over `TRUSTS` renders six
  options with i18n labels.
- `ConfirmDialog`: `onConfirm` not called without a reason when
  required, called with it when given (pair); Escape cancels; focus
  returns to the opener; destructive variant does not autofocus the
  primary.
- `axe` on every field state (idle, invalid, disabled); both languages.
- Browser tests: a zone-shaped form with ED-318 fields and API errors replayed
  from a fixture problem body; an intent-shaped form with the ten
  Annex IV items as plain fields (labels only; the schema is the app's);
  a source switch confirm; golden DOM snapshots.

## Safety notes

A form is where a client-side "helpful" check becomes a second copy of a
rule (T12). The kit validates shape; the API validates meaning with the
strict readers in `uspace-core` and names every field it refuses; the
form's job is to put that refusal on the right field, all of it, in
the operator's language. The `ConfirmDialog` with a reason is how B-11's
"disabled by a person" gets its person and its why.

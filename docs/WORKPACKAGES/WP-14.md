## What to build

- `semver-gate.mjs`, run in CI on pull requests: diff
  `docs/api/uspace-ui.api.md` against the base; a removed or changed
  line (not an added one) requires a new `## [N.0.0]` heading under
  `Unreleased` in `CHANGELOG.md` and the PR label `breaking`; a diff
  under `styles/tokens.css` touching a `--us-severity-*`, `--us-trust-*`,
  `--us-ident-*`, `--us-zone-*` or `--us-age-*` value, or under
  `src/symbology/` touching a `*Token`/`*Shape`/`*Pattern` return,
  requires the label `legend-change` and a CHANGELOG line that cites a
  LESSONS id or a spec row; the script prints exactly which rule fired
  and why (E-04). Before `v1` the same script requires a minor heading
  instead (PLAN §12).
- `src/test/fixtures/`: `fixtures()` now built from the lab's examples
  at `docs/LAB_VERSION` (`track/telemetry/v1`, `track/manned/v1`,
  `alert/v1`, `violation/v1`, `cis/change/v1`, `source/status/v1`, the
  ED-318 round-trip example) through the same adapters a `web/` would
  write (`src/test/adapters/*.ts`, the reference adapters, exported from
  `/test` as examples); a `sync-fixtures.sh` with `VERSION` and
  `SHA256SUMS` like core's vector sync; `check-fixtures.sh` offline
  (checksums) and online (diff against the lab at the pinned commit),
  required on `main`.
- Every story and component test that used synthetic fixtures runs
  against the lab-derived ones too (the `fixtures()` signature is
  unchanged; both sets are exported, `fixtures({ source: "lab" })`).
- `check-enums.sh` hardened: parse `uspace-core/core` at the tag with a
  proper tokenizer (a Go `const` block reader in Node), compare every
  enumeration, print a table, fail on any difference; required on
  `main`, best-effort on PRs as before.
- API freeze: every export in §3 tagged `@public`; anything else
  `@beta` and excluded from the semver gate; `api-extractor` config set
  to fail on an untagged export.
- `CHANGELOG.md` `1.0.0` with the compatibility policy copied from
  PLAN §12; `release/v1` branch policy documented in `CLAUDE.md`.

## Tests

- `semver-gate.test.ts`: fixture diffs for each rule, each with a
  passing and a failing variant (E-01): an added line passes without a
  label; a removed line fails without `breaking` and passes with it and
  the heading; a token value change fails without `legend-change`; a
  comment change in `symbology/` passes; the printed reason names the
  rule.
- `fixtures.lab.test.ts`: every lab example decodes through the
  reference adapters without a thrown error and without an `unknown`
  enumeration value (a value the kit cannot name fails here: that is
  the conformance hook of `04 §4`); every enumeration value in `model`
  appears in at least one example, or the test lists the missing ones
  as a visible warning with the lab issue to file (the lab owns
  coverage; the kit reports it).
- `check-enums` against a deliberately edited local copy of the core
  constants fails (presence twin for the online check).
- The whole browser suite re-run on the lab fixtures: no new `axe`
  failure, no new snapshot change (a change here means a real-world
  shape the synthetic set missed: investigate, do not re-baseline
  blindly).

## Safety notes

The gate is what makes "additive within a major" true rather than
hoped. The lab fixtures are the conformance hook: a message shape the
lab can emit and the kit cannot render is found here, before a console
shows a blank where an aircraft should be. The enum check keeps the
four statuses, six trust classes and fifteen reasons identical to the
Go source that decides them; a drift there is a status that exists on
the bus and not on the screen.
